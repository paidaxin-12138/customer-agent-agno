## 问题 1：平台「文明用语」不误标已回复

### 现象

用户发送不当用语后，拼多多平台自动插入「请文明用语」系统消息。该消息被当作客服已回复，导致用户真实提问未被 AI 处理。

### 涉及文件

| 文件 | 说明 |
|------|------|
| `utils/platform_system_msg.py` | **新建**，识别平台文明提示 |
| `Channel/pinduoduo/pdd_chnnel.py` | WS 入站处理 |
| `database/chat_persist.py` | 持久化 `sender_type=system` |
| `ui/conversation_hub.py` | 会话 Hub 登记 |
| `Message/handlers/ai_handler.py` | AI 入口跳过文明提示 |

### 实现要点

1. **`is_platform_civility_message(context)`**  
   识别 `mall_system_msg` / `mall_cs` / `system_hint` 且内容含「文明用语」「请文明」「文明沟通」等关键词。

2. **`pdd_chnnel._process_websocket_message`**  
   - 检测到文明提示 → `mark_platform_civility_context(context)`  
   - 调用 `conversation_hub.record_platform_civility_from_context()`  
   - **不**设置会话已回复标志（不触发 outbound watchdog）

3. **持久化**  
   - `sender_type='system'`，不计为商家有效回复  
   - 平台 `mall_cs` 文明提示不再写入 `human` 侧记录

4. **`AIReplyHandler`**  
   - 入口 `_resolve_effective_buyer_query()` 若当前为文明提示，跳过该条  
   - 合并未回复买家消息后继续处理

### 关键代码

```python
# utils/platform_system_msg.py
CIVILITY_MARKERS = ("文明用语", "请文明", "文明沟通", "文明聊天")

def is_platform_civility_message(context) -> bool:
    text = extract_context_text(context)
    if not is_platform_civility_content(text):
        return False
    return context.type in (MALL_SYSTEM_MSG, SYSTEM_HINT, MALL_CS)
```

## 问题 2：链路丢失 / 锁释放 / ai_mode

### 现象

- 同买家消息串行处理时，异常可能导致锁未释放  
- 消息未处理时缺少明确日志  
- `ai_mode` DB 检查失败时误跳过 AI

### 涉及文件

| 文件 | 说明 |
|------|------|
| `Message/core/consumer.py` | 消费者锁与日志 |
| `config.py` | `ai_mode_check_fail_open` 默认改 `true` |
| `Message/handlers/ai_handler.py` | AI 处理链路 |

### 实现要点

1. **`_process_message` 使用 `lock.acquire()` + `try/finally`**  
   确保任何异常下都 `lock.release()`。

2. **处理完成日志**  
   ```text
   Message {id} 处理完成 processed={True/False} user_key={...}
   ```

3. **`processed=False` 时**  
   调用 `Message/handlers/fallback_reply.try_send_unhandled_fallback()`。

4. **`ai_mode` 检查**  
   - 配置项 `chat.ai_mode_check_fail_open` 默认 **`true`**  
   - DB 临时异常：记录日志，**允许 AI 继续**（除非会话明确 `ai_mode=False`）

### 关键代码

```python
# Message/core/consumer.py
await lock.acquire()
try:
    ...
finally:
    lock.release()
    self.logger.info(
        "Message {} 处理完成 processed={} user_key={}",
        wrapper.message_id, processed, user_key,
    )
```

## 问题 3：AI 回复速度优化

### 现象

AI 回复等待超过 30 秒；LLM 并发过高；RAG 检索阻塞。

### 涉及文件

| 文件 | 说明 |
|------|------|
| `config.py` / `config.json.example` / `.env.example` | 新配置项 |
| `Agent/CustomerAgent/agent.py` | LLM 参数与 RAG 超时 |
| `Channel/pinduoduo/pdd_chnnel.py` | 消费者并发默认值 |
| `Message/core/consumer.py` | 默认 worker 数 |
| `ecosystem.config.js` | PM2 环境变量 |

### 实现要点

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `chat.ai_max_tokens` | `500` | 覆盖 LLM 生成长度 |
| `chat.ai_temperature` | `0.5` | 覆盖 LLM 温度 |
| `chat.knowledge_retrieval_timeout_sec` | `5` | RAG 超时秒数 |
| `chat.message_consumer_max_concurrent` | `16` | 原 28，降低 API 并发压力 |
| `llm.model_name` | `qwen-turbo` | 示例配置，可换 `deepseek-chat` |

- Agent 初始化时优先读 `chat.ai_max_tokens` / `chat.ai_temperature`  
- 知识库检索：`asyncio.wait_for(asyncio.to_thread(...), timeout=...)`，超时跳过 RAG，仅用 LLM  
- `ecosystem.config.js` 增加 `LLM_MODEL_NAME`、`LLM_MAX_TOKENS`、`MESSAGE_CONSUMER_MAX_CONCURRENT`

### 关键代码

```python
# Agent/CustomerAgent/agent.py
async def _search_async():
    return await asyncio.wait_for(
        asyncio.to_thread(km.search_knowledge, q, top_k=limit),
        timeout=timeout_sec,
    )
```

## 问题 4：合并未回复买家消息

### 现象

用户连续发多条消息，AI 只回复最后一条，遗漏前面未回复的提问。

### 涉及文件

| 文件 | 说明 |
|------|------|
| `utils/unreplied_buyer_messages.py` | **新建**，未回复消息合并 |
| `Message/handlers/ai_handler.py` | 调用合并逻辑 |

### 实现要点

1. **`get_unreplied_buyer_messages(session_id, max_count=3)`**  
   - 扫描最近 5 条买家消息  
   - 找出**最后一条有效客服回复**（`ai`/`human`，排除平台文明提示）之后的买家消息  
   - 返回最多 3 条，时间升序

2. **合并 Prompt 格式**  
   ```text
   用户先问：...
   然后问：...
   然后问：...
   请一并回答。
   ```

3. **长度限制**  
   - 总长度不超过 **2000 字符**  
   - 超出时**优先丢弃较早的消息**（保留最新未回复内容）

### 关键代码

```python
# utils/unreplied_buyer_messages.py
def get_unreplied_buyer_messages(session_id: int, max_count: int = 3) -> List[str]:
    rows = db_manager.get_chat_messages_recent(session_id, limit=...)
    return collect_unreplied_buyer_messages(rows, max_scan=5, max_parts=max_count)
```

## 问题 5：AI 上下文完整时间

### 现象

消息时间仅 `HH:MM`，AI 无法区分「今天」与「昨天」。

### 涉及文件

| 文件 | 说明 |
|------|------|
| `utils/chat_time.py` | 时间格式化工具 |
| `Agent/CustomerAgent/conversation_memory.py` | 短期记忆注入 AI |
| `ui/widgets/chat_bubble_widgets.py` | UI 气泡时间展示 |

### 实现要点

| 函数 | 用途 |
|------|------|
| `format_chat_iso(t)` | AI 上下文：`YYYY-MM-DD HH:MM:SS` |
| `format_chat_display_relative(t)` | UI：`今天 14:30` / `昨天 18:30` / `05-28 14:30` |

- 短期记忆每行：`[2026-05-30 14:30:05] 买家：...`  
- 本轮消息时间：`【本轮消息时间】2026-05-30 14:30:05`  
- UI 气泡保持简洁相对时间，**传给 AI 的必须是完整 ISO 时间**

## 问题 6：减少「找产品经理」误转人工

### 现象

知识库未覆盖的问题频繁触发「找产品经理」或转人工弹窗。

### 涉及文件

| 文件 | 说明 |
|------|------|
| `Message/handlers/ai_handler.py` | Fallback 逻辑 |
| `utils/llm_errors.py` | 产品经理话术替换 |
| `utils/human_transfer_intent.py` | 显式转人工意图 |
| `Agent/CustomerAgent/agent.py` | `_KNOWLEDGE_GROUNDING` 提示词 |
| `config.py` | 兜底配置 |

### 实现要点

1. **新增配置**  
   | 配置项 | 默认值 |
   |--------|--------|
   | `chat.ai_fallback_to_human_on_unknown` | `false` |
   | `chat.ai_unknown_fallback_notice` | `亲，我暂时还不清楚，您可以描述得更详细些，或者我帮您转人工客服？` |

2. **`has_explicit_transfer_intent(text)`**  
   识别「转人工」「找经理」「人工客服」等**明确要求**。

3. **Fallback 规则**  
   - 仅 `has_explicit_transfer_intent(user_question)==True` → `_escalate_immediate`（弹窗转人工）  
   - 其他无法回答 → 发送 `ai_unknown_fallback_notice`，**不转人工**

4. **LLM 回复后处理**  
   - 回复含「产品经理」→ `sanitize_ai_reply_content()` 替换为兜底话术  
   - 记录日志，不触发转人工

5. **Agent 提示词**  
   `_KNOWLEDGE_GROUNDING` 移除「建议联系产品经理」类表述，改为通用未知话术。

### 关键代码

```python
# utils/human_transfer_intent.py
def has_explicit_transfer_intent(text) -> bool:
    return detect_human_transfer_intent(text) or detect_manager_escalation_intent(text)

# Message/handlers/ai_handler.py
async def _handle_unknown_ai_failure(...):
    if has_explicit_transfer_intent(q):
        return await self._escalate_immediate(...)
    notice = get_ai_unknown_fallback_notice()
    return await self._send_reply(context, notice, metadata)
```

## 部署与升级注意

1. **已有 `config.json`**  
   不会自动覆盖已有键；请手动合并上述新配置，或删除 `config.json` 后由程序从 `config_base` 补全默认值（会丢失自定义项，请先备份）。

2. **模型切换**  
   通过 `config.json` 的 `llm.model_name` 或 `.env` 的 `LLM_MODEL_NAME` 设置，如 `qwen-turbo`、`deepseek-chat`。

3. **PM2 部署**  
   `ecosystem.config.js` 已预置 `LLM_MODEL_NAME`、`LLM_MAX_TOKENS`、`MESSAGE_CONSUMER_MAX_CONCURRENT`；可按环境修改。

4. **验证**  
   ```bash
   uv sync
   uv run python -m pytest test/ -q
   # 期望：179 passed
   ```

5. **手动验证建议**  
   - 发送含脏话消息 → 平台文明提示出现后，AI 仍应回复用户真实问题  
   - 连续发 2～3 条未回复消息 → AI 应合并理解并一并回答  
   - 问知识库外问题 → 应收到兜底话术，不应弹「找产品经理」  
   - 明确说「转人工」→ 应触发转人工流程
