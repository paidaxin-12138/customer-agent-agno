# 转接截流与浏览器盯盘

## 目标

- **浏览器**：子账号登录商家后台，**可查看、可盯盘**（与软件同时显示会话列表）。
- **本软件**：同一店铺的**接待子账号**「上线 + 开始回复」；收到转接后**自动截流**，由 AI/规则链处理买家消息。
- **双端展示（可选，默认关）**：`mms_session_sync_enabled=true` 时，软件只读拉取 MMS `latest_conversations` 写入本地库，**不会**调用转接、不会改变网页上会话归属。

## 工作原理

1. 售前在拼多多将买家**转接**到接待子账号（`seller_user_id` 须在 `chat.preferred_transfer_seller_user_ids` 或即为软件监听账号）。
2. 本机 WebSocket 收到 `TRANSFER` → 写系统消息并标记 `inbound_transferred_at` → **`apply_inbound_transfer_takeover`** 才截流：
   - `stage` → `idle`（含历史脏数据 `general` 的规范化）
   - `ai_mode` → `True`（当 `inbound_transfer_takeover_ai_mode` 为 true）
   - 本地**未回复**买家消息 → 重新入队，走责任链
3. **转接前拦截（默认开）**：`preferred_transfer_seller_user_ids` 中的接待号，在收到 TRANSFER 之前**不**走 AI/规则责任链（日志 `[GATE]`）；售前直接进线的会话只记录、不自动回复。
4. 之后买家新消息优先走 WebSocket 入队 → `AIReplyHandler` 等处理。

## 必做配置（`config.json` → `chat`）

```json
"preferred_transfer_seller_user_ids": ["你的接待子账号 seller_user_id"],
"inbound_transfer_force_takeover": true,
"inbound_transfer_takeover_ai_mode": true,
"inbound_transfer_enqueue_unreplied": true,
"inbound_transfer_default_manual": false,
"inbound_transfer_gate_until_received": true,
```

将 `preferred_transfer_seller_user_ids` 换成实际接待号；AI/规则**主动转出**时也会优先转给这些号。

## 操作清单

| 步骤 | 说明 |
|------|------|
| 1 | 自动回复：接待号 **上线** → **开始回复**（显示「停止回复」） |
| 2 | 实时聊天顶部应为 **消息通道：已连接** |
| 3 | 浏览器：可**与软件同时**打开会话列表盯盘；软件会自动 MMS 同步，无需关网页 |
| 4 | 转接目标 = 软件正在监听的那个子账号 |
| 5 | 修改配置后 **重启应用** |

## 日志验收

转接后应出现（示例）：

```
转接消息 shop=... buyer=...
转接接管: session=... stage=idle ai_mode=True
转接接管已入队未回复处理: ...   # 有本地未回复时
handled by AIReplyHandler transfer_takeover   # 或普通 AI 处理
```

不应长期出现：`未被任何 handler 处理 stage=general`（仅安抚）。

## 限制

- MMS 同步仅含各会话**最后一条**摘要，不是全量历史；打开会话后仍主要依赖本地已入库消息 + WebSocket 新消息。
- 网页若在**同一子账号**上抢 WebSocket（日志 `auth result: fail`），实时推送会弱于软件；请保持软件「开始回复」，并依赖 MMS 轮询补展示/补入队。
